# `@cluster-mkt/web`

Responsive React/Vite browser shell for Today, Story Cluster detail, navigation, settings previews, edition accents, and honest demonstration fixtures. It consumes `@cluster-mkt/core`, `@cluster-mkt/config`, `@cluster-mkt/ui`, and canonical assets under `brand/`.

The shell is implemented but has no live feeds, persistence, authentication, AI, audio generation, or publisher connections. `public/brand/` is generated by `pnpm assets:sync` and must not be edited or committed.

`/sectors` and `/sectors/semiconductors` demonstrate scope-aware sector coverage and a shared edition brief using deterministic fixtures. Frontend acceptance requires controlled-browser checks at desktop and mobile sizes, including console and network inspection.

`/dev/normalization` is a direct-only developer fixture inspector for raw and normalized source records, URL decisions, duplicate/syndication and version state, entity adjudication, event signatures, and decision traces. It is deliberately absent from primary consumer navigation and makes no publisher request.

`/dev/clusters` is a second direct-only developer fixture inspector. It exposes candidate membership, evidence-depth-qualified claims, independent support, agreement, disagreement, uncertainty, review routing, and claim-to-source paths using offline demonstration data. Consumer cluster pages use validated supported-claim fixtures while preserving their existing navigation and visual hierarchy.

`/dev/ingestion` is a third direct-only developer fixture inspector. It shows the offline operational registry selection, mock adapter attempts, retrieval provenance, retry and circuit-breaker timeline, quarantine, idempotency ledger, checkpoints, interrupted-run resume, reconciliation, and explicit zero-live/zero-credential/zero-network status. It performs no retrieval and is absent from consumer navigation.

`/dev/review`, `/dev/review/:itemId`, and `/dev/adjudication` form a direct-only reviewer-workflow demonstration. They show candidate coverage, blinded evidence, independent annotation controls, cannot-determine and confidence fields, adjudication gating, and honestly pending agreement/calibration state. Local component state is not authentication, persistence, or a human gold label.

`/dev/agent-panels` and `/dev/agent-panels/:itemId` form a direct-only blind multi-agent calibration pilot dashboard. They show worker-isolation status, reviewer roles, panel outcomes, dissent, isolated adjudication with anonymized panel-member ids only, owner escalation, packet hashes, and repeat-run stability using offline demonstration data drawn from the pilot. Agent reviewers are always labeled as agents, results are always labeled provisional, and the pages are absent from consumer navigation.
